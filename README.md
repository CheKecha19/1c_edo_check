# Сверка пользователей 1С и ЭДО

Консольный скрипт для администратора. Проверяет, у кого остался активный доступ к 1С, Контур.Диадоку или Сфера Курьер. Результат — Excel-отчёт для ручной проверки. Решение о блокировке принимает администратор.

## Правила сверки

- Штатного сотрудника подтверждает присутствие в актуальном штатном расписании. Для исполнителя по ГПХ основанием служит включённая учётная запись в ветке ГПХ Active Directory. Расхождения между штаткой и AD выводятся отдельно в обе стороны.
- В 1С статус читается по заголовку «Недействителен». Значение «Нет» означает активную учётку, «Да» — неактивную. В Excel Диадока скрипт проверяет дату блокировки, в Сфере — поле «Активен».
- Активная учётка попадает на проверку доступа, когда оба кадровых источника проверены и человека нет ни в одном. Совпадение в доступном источнике подтверждает основание. Непрочитанный статус, неоднозначное ФИО или отсутствие необходимого источника дают результат «Недостаточно данных».
- ФИО сравниваются с учётом отчества, без различий в регистре, пробелах и буквах «е»/«ё». По фамилии и имени допускается однозначное совпадение, когда в одной из записей отсутствует отчество.

## Запуск

Потребуются Windows с PowerShell, Python 3.9+ и доступ на чтение к домену для экспорта AD. В `ad_export.py` штатные выбираются из OU `cu_users`, а ГПХ — из OU `external_organizations` или OU с «ГПХ» в названии. Проверьте эти имена для своего домена.

1. Распакуйте проект и замените примеры своими актуальными выгрузками `.xlsx`.

   | Папка в `эксельки/` | Данные |
   |---|---|
   | `штатка/` | Штатное расписание со столбцом «Ф.И.О.» или «ФИО» |
   | `1С/` | Лист «Лист_1», заголовки «Пользователь» и «Недействителен» |
   | `эдо_контур_диадок/` | ФИО и дата блокировки |
   | `эдо_сфера_курьер/` | ФИО и признак «Активен» |

2. В папке проекта выполните

   ```powershell
   python -m pip install -r requirements.txt
   python main.py
   ```

3. Выберите системы и категории сотрудников. Фильтр категории оставляет в оценке записи с неподтверждённой принадлежностью, чтобы их можно было проверить вручную.

По умолчанию для каждого источника выбирается последняя по времени изменения таблица за 180 дней. Порог задаётся в `config.py`. Там же включаются API ЭДО через `USE_DIADOC_API` и `USE_SFERA_API`. Параметры доступа задаются в окружении или в локальном `.env` — `DIADOC_API_KEY`, при необходимости `DIADOC_BOX_ID`, либо `SFERA_USERNAME` и `SFERA_PASSWORD`.

## Результат

Откройте новый файл `вывод/результат_обработки_*.xlsx`. Лист **«Источники»** показывает полноту загрузки. На листе **«Оценка доступа»** у каждой учётки указаны основание, статус и результат. При наличии записей создаются листы **«удалить из …»**, **«Недостаточно данных»** и листы возможных дублей. Журналы запуска находятся в `вывод/log/`.
